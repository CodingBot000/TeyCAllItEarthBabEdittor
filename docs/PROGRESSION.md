## 2. 흡수 종류별 보상

아래 값은 **기본 템플릿 1,000 흡수 단위당** 값이다. `프로필 보상배율 × (1 + selective-filter 레벨×0.12)`를 전 항목에 곱한다. 최종 임무 회수 때는 항목별로 내림한다.

| 종류 | 무게 | 포로 | 바이오매스 | 합금 | 정보 | 코어 | 기본 개방 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| ORGANIC | 1 | 1,000 | 0 | 0 | 0 | 0 | 방공호 파괴. 외부 군중은 즉시 |
| VEHICLE | 12 | 0 | 2 | 7 | 0 | 0 | 제한 없음 |
| MACHINERY | 18 | 0 | 0 | 9 | 1 | 0 | 제한 없음 |
| POWER | 24 | 0 | 0 | 0 | 0 | 1.2 | 제한 없음 |
| DATA / radar | 3 | 0 | 0 | 1 | 8 | 0 | 연결 RADAR가 살아 있고 EMP 정지 중 |
| DATA / archive | 3 | 0 | 0 | 2 | 10 | 0 | 위와 같음 |
| RELIC | 6 | 0 | 2 | 3 | 12 | 0 | 연결 AIRBASE 파괴 |

무게는 빔 열 증가에 사용하며 화물 단위에 곱하지 않는다. 선택 필터는 포로·코어까지 증가시킨다. 따라서 실제 흡수 인구와 최종 포로 보상이 같지 않을 수 있다.

외부 군중은 현재 공통 ORGANIC 보상으로 직접 등록해 Desert 프로필의 템플릿 배율 1.12를 거치지 않는다. 도시 자원 풀도 우회한다. [SYS-003](GAPS.md#sys-003)

### 프로필 차이

| 프로필 | ORGANIC/VEHICLE/MACHINERY/POWER/DATA/RELIC 가중치 | 공중 압력 | 지상 배율 | 템플릿 보상 | 필수 거점 |
| --- | --- | ---: | ---: | ---: | ---: |
| Coastal | 5 / 3 / 2 / 2 / 1 / 1 | 1 | 1 | 1 | 2 |
| River | 3 / 2 / 4 / 4 / 2 / 1 | 1.05 | 1.12 | 1 | 2 |
| Desert | 2 / 2 / 2 / 5 / 4 / 3 | 1.15 | 1.2 | 1.12 | 3 |

가중치는 종류 선택 확률과 초기 종류별 자원 풀 크기에 사용한다. 모든 종류가 매번 생성된다는 보장은 없고, 방공호 두 슬롯 우선 규칙도 있다. 지상 배율은 적 GroundDefender 체력·공격과 아군 지상 드론 피해에 모두 연결된다.

초기 풀은 템플릿 종류별 `baseAmount` 합계에 도시 자원 보정과 프로필 가중치 보정을 곱해 반올림한다. ORGANIC은 도시 기준 인구, DATA/RELIC은 기술 등급, 나머지는 자원 등급을 사용한다. 도시 전체 잔존 인구와 이 추상 자원 풀은 별도 수치다.

## 3. 포로 배분과 코호트

회수 포로를 아래 세 목적지에 **정확히 남김없이** 배분해야 한다.

```text
코호트 수 × 5,000 + 바이오매스 투입 인원 + 보관 인원 = 이번 회수 포로 수
바이오매스 = 투입 인원 / 100 (투입은 반드시 100명 단위)
```

코호트 수는 이번 배분에서 `conversionCapacity` 이하. 생성된 병력은 `ASSAULT/RESERVE`, 기본 전력·응집력·통제 각각 100, 경험치 0이다. conditioning은 **새 코호트 초기 전력**에도 반영된다. 기존 병력 전력을 구매 즉시 회복·상향하는 명령은 없다.

| 교리 | 우선 코호트 배분 비중 | 코호트 배분 후 예비 보관 비중 |
| --- | ---: | ---: |
| LEGION 군단 집중 | 70% | 10% |
| BALANCED 균형 | 40% | 35% |
| SUSTAIN 유지 | 20% | 70% |

비중은 확정 결과가 아니라 기본안 생성에 쓰인다. 코호트는 5,000 단위로 내림하고 생성 상한을 적용하며, 나머지 중 예비 인원을 고르고 잔여를 바이오매스로 처리한다. UI에서 코호트 ±1, 예비 인원 ±100을 조정할 수 있다. 수동 조정해도 `doctrine` 명칭을 자동으로 CUSTOM으로 바꾸지는 않는다.

주의사항:

- 예비 포로를 나중에 꺼내 변환하는 화면·규칙이 없다. ‘나중 전환을 위해 보관’ 문구와 불일치한다. [SYS-007](GAPS.md#sys-007)
- 예비고가 가득 차고 회수 인원에 100 미만 나머지가 있으면 합계와 배수 조건을 동시에 만족할 수 없다. [SYS-002](GAPS.md#sys-002)
- conditioning 1레벨만 있어도 새 병력 전력은 108인데 저장 스키마 상한은 100이다. [SYS-001](GAPS.md#sys-001)
- 경험치·통제값은 저장·표시하지만 현행 피해나 승급에 사용되지 않는다. 응집력·전력은 피해와 생존에 실제 사용된다.
- 주둔 코호트는 다음 출격의 예비 병력 목록에서 제외된다. 다시 예비로 회수하는 플레이 명령은 없다.

## 4. 업그레이드 구매 규칙

카탈로그 26종, 트리 분기 6개, **모든 노드 최대 3레벨**. 선행 조건은 최초 구매(레벨 0→1)에 검사한다. 이전 저장에 이미 보유한 노드는 현재 선행 조건이 충족되지 않아도 다음 레벨을 살 수 있다. 이는 기존 보유 노드를 보존하는 호환 규칙이다.

구매하면 즉시 지갑에서 비용을 차감하고 저장한다. 연구 시간·대기열·장착 슬롯·환불·초기화·상호 배타 노드는 없다. 효과는 구매한 레벨 전부 누적 적용한다.

비용 표의 순서는 **바이오매스 / 합금 / 정보**. ‘기본비용×n’에서 n은 구매할 레벨 1·2·3이다. 예외 3종은 별도 표에 전 레벨 비용을 기록했다.

## 5. 기획 판단 전에 확인할 연결

- 코어 충전에는 실제 이동 소비처가 있다. ‘코어가 전혀 쓰이지 않는다’는 결론은 맞지 않는다. 문제는 셀 구매와 전투 소비의 연결이다.
- 포로 예비고·주둔·경험치에 사용 경로를 추가할지, 현재 설명과 UI를 축소할지 결정해야 한다.
- 위협 예측은 실제 경보 감소가 아니다. 현행 HUD와도 미연결이므로 비용을 지불하는 업그레이드로 유지할 근거를 재검토해야 한다.
- 열 효율, 에너지 소비 효율, 자원 보상 효율은 서로 다른 효과다. 카드 이름만으로 합치지 않는다.
- 새 업그레이드를 더하기 전에 기존 26종의 효과·저장·화면 설명을 일치시켜야 한다. [GAPS](GAPS.md)에 구체적인 완료 조건을 기록했다.
