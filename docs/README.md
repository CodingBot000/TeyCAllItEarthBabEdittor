## Codex가 작업을 시작할 때

1. 이 안내 → 전체 구성 → 변경할 시스템 문서를 읽는다.
2. 관련 `SYS-xxx` 항목을 확인하고, 문서에 링크된 코드의 현재 호출 경로를 다시 확인한다.
3. **현재 사양**을 바꾸는 작업인지 **미구현 기획**을 연결하는 작업인지 구분한다. 타입·에셋·번역만 있는 기능을 실행 기능으로 취급하지 않는다.
4. 코드 변경 시 해당 시스템 문서와 개선 항목의 상태·근거·검증 결과를 함께 갱신한다. 완료된 작업을 별도 계획서나 거대한 일지에 중복 기록하지 않는다.

## 날짜와 변경 이력 관리

- 작성일은 최초 작성 날짜로 유지한다. 루트 README의 ‘현행본 작성일’은 이번 전면 개정본의 날짜이며 기존 파일의 최초 생성일을 뜻하지 않는다.
- 문서를 수정할 때 상단의 최종 수정일을 갱신하고 변경 이력 표 맨 위에 날짜·구분·주요 변경 내용을 추가한다. 이전 이력은 지우거나 덮어쓰지 않는다.
- 날짜는 한국 시간(Asia/Seoul)의 `YYYY-MM-DD` 형식으로 기록한다. 같은 날의 별도 수정도 구분과 내용으로 남긴다.
- 코드 기준일·기준 커밋은 문서 수정일과 별개다. 날짜 표기나 문장만 고쳤을 때 코드 재검증까지 한 것으로 갱신하지 않는다.
